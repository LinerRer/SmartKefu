## 一、项目背景

中小企业在线客服普遍存在以下痛点：

1. **重复问题占比高**：售前咨询（价格、规格、发货、售后政策）高度重复，占用大量人工；
2. **人力成本高、夜间无人值守**：非工作时间无人响应，丢失潜在客户；
3. **响应不及时**：用户等待时间长，体验差；
4. **知识分散**：产品资料、FAQ、政策散落在不同文档中，新客服上手慢。

随着大模型（LLM）与检索增强生成（RAG）技术成熟，基于企业自有知识库的 AI 客服已能稳定处理大部分标准化咨询。本项目构建一个 **AI 自动应答为主、人工坐席兜底、工单可追踪** 的智能客服系统，覆盖"知识库 → AI 应答 → 转人工 → 工单 → 数据统计"完整闭环。

---

## 二、项目目标

| 目标 | 说明 | 指标性质 |
|---|---|---|
| AI 自动应答 | 基于知识库自动解答业务咨询，支持多轮对话 | 核心功能 |
| 高独立解决率 | 尽量减少人工介入，目标 AI 独立解决率 **≥ 70%** | 目标值（需实测） |
| 流式响应 | 答案逐字流式输出，降低等待感，目标首字响应 **≤ 2 秒** | 目标值 |
| 平滑转人工 | AI 答不了或用户主动要求时，可转人工坐席 | 核心功能 |
| 工单闭环 | 无人在线 / 无法解决时自动生成工单，可追踪处理 | 核心功能 |
| 知识库自助管理 | 文档上传、解析、向量化、FAQ 管理、检索测试 | 核心功能 |
| 数据可量化 | 会话量、解决率、转人工率、满意度等看板 | 核心功能 |
| 可部署上线 | 容器化（Docker Compose）部署到云服务器 | 工程目标 |

> 说明：所有带具体数值的指标均为**设计目标**，需在开发完成后通过真实评测集和压测验证，不以未验证的数字对外宣称。

## 三、用户角色

| 角色 | 说明 | 登录方式 |
|---|---|---|
| 访客（客户） | 访问网站、咨询问题的终端用户 | 无需注册，系统分配会话 Token |
| 人工客服（坐席） | 接待转人工会话、处理工单 | 账号密码 + JWT 登录 |
| 管理员 | 管理知识库、坐席账号、查看数据看板 | 账号密码 + JWT 登录（更高权限） |

## 四、功能需求

### 4.1 访客端（C 端聊天窗口）

| 编号 | 功能点 | 功能描述 | 优先级 |
|---|---|---|---|
| F-01 | 发起会话 | 打开聊天窗口即创建会话，系统分配会话 ID 与 Token | P0 |
| F-02 | 在线问答 | 发送消息，AI 基于知识库回答 | P0 |
| F-03 | 流式接收 | 回答逐字流式显示（SSE），支持"正在输入"状态 | P0 |
| F-04 | 多轮对话 | 支持上下文关联（如"它多少钱"能理解"它"指代） | P0 |
| F-05 | 引用溯源 | AI 回答可展开查看来源文档片段 | P1 |
| F-06 | 常见问题引导 | 首次进入展示推荐问题，点击可直接发送 | P1 |
| F-07 | 申请转人工 | 点击"转人工"按钮，进入人工排队 / 工单 | P0 |
| F-08 | 状态提示 | 显示"AI 在线 / 排队中 / 人工已接入 / 留言" | P0 |
| F-09 | 满意度评价 | 会话结束后可点赞 / 点踩 + 标签（可选） | P1 |
| F-10 | 历史消息 | 刷新页面后可恢复本次会话历史 | P1 |

### 4.2 AI 客服核心

| 编号 | 功能点 | 功能描述 | 优先级 |
|---|---|---|---|
| A-01 | 知识库问答（RAG） | 检索知识库 → 组装上下文 → LLM 生成答案 | P0 |
| A-02 | 混合检索 | 向量语义检索 + BM25 关键词检索，分数融合 | P0 |
| A-03 | 结果重排（Rerank） | 用 Rerank 模型对召回结果精排，提升相关性 | P0 |
| A-04 | 多轮记忆 | 管理对话历史，按需携带上下文 | P0 |
| A-05 | 意图识别 | 识别：业务咨询 / 闲聊 / 转人工 / 超出知识库范围 | P0 |
| A-06 | 自动转人工 | 答不出、连续未命中、用户情绪激烈时自动转人工 | P0 |
| A-07 | 引用溯源 | 答案标注来源，无来源时走兜底话术 | P0 |
| A-08 | 兜底策略 | 知识库无相关内容时不强行编造，明确告知并引导 | P0 |
| A-09 | 幻觉抑制 | 业务事实以知识库为准，Prompt 约束 + 后处理 | P1 |

## 五、核心业务流程

### 5.1 主对话流程

```
访客打开聊天窗口
        │
        ▼
   创建会话（分配会话 Token）
        │
        ▼
   访客发送消息 ──► 意图识别
        │
        ├─ 业务咨询 ──► RAG 检索
        │                 │
        │                 ├─ 命中（相关度达标）──► LLM 生成答案（流式 + 引用）──► 回到对话
        │                 └─ 未命中（连续 N 次）──► 自动转人工
        │
        ├─ 主动转人工 ──► 排队 / 接入
        │
        └─ 闲聊/超范围 ──► 礼貌引导 / 转人工
        │
        ▼
   转人工：
   ├─ 有坐席在线 ──► 人工接管（WebSocket）──► 解决 ──► 结束
   └─ 无坐席在线 ──► 生成工单（留言）──► 后续处理
        │
        ▼
   会话结束 ──► 满意度评价 ──► 数据落库（看板统计）
```

### 5.2 知识库构建流程

```
上传文档 → 解析文本 → 递归分块 → 生成 Embedding → 写入向量库
                                          └──── BM25 索引同步构建
FAQ 问答对 ─────────────────────────────► 直接入库（精确匹配优先）
```

## 六、非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 目标首字响应 ≤ 2 秒；单机能支撑开发联调，记录并发数据 |
| 实时性 | AI 回答使用 SSE 流式；人工聊天使用 WebSocket |
| 可用性 | 大模型 / 检索失败有兜底，不返回报错堆栈给用户 |
| 安全性 | 管理端 JWT 鉴权；访客会话隔离；密码加密存储；接口限流 |
| 可观测性 | 结构化日志、Trace 链路 ID、关键操作记录、异常记录 |
| 可维护性 | 分层架构、配置集中管理、统一响应与异常处理 |
| 可部署性 | Docker Compose 一键编排，可在 Linux 云服务器部署 |
| 可测试性 | 核心模块单元测试（pytest），关键链路有评测 |

## 七、范围边界

### v1.0（本期实现）

- 单租户：一套系统服务单一企业
- 访客 Web 聊天窗口 + 管理端（知识库 / 坐席 / 工单 / 看板）
- AI 知识库问答（混合检索 + Rerank + 多轮 + 流式 + 引用）
- 转人工（WebSocket）+ 工单系统
- JWT 鉴权、Redis 缓存、数据看板
- Docker Compose 部署上线

### v2.0（本期不做，写入 Roadmap）

- 多租户 / SaaS 化与计费
- 多渠道接入（微信公众号、小程序、抖音、企业微信）
- 语音通话 / 语音转文字
- 知识库自动学习（从历史人工会话中挖掘新问答）
- 更完善的坐席质检、排班与分配
- 大规模分布式（消息队列、多实例）

---

## 八、验收标准（项目级）

1. 访客可完成完整的"提问 → AI 流式回答 → 转人工 / 留言 → 评价"流程；
2. 上传一份真实业务文档后，能正确回答文档内问题，并标注来源；
3. 知识库无答案时不编造，能引导转人工 / 生成工单；
4. 坐席可在工作台实时接管并收发消息；
5. 数据看板能展示真实统计数据；
6. 系统可通过 Docker Compose 在云服务器上公网访问；
7. 关键指标（解决率、首字响应）有真实评测数据，可复现。
